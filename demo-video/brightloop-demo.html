The problem

Subscriptions are deceptively hard.

Bill every customer, every period — never twice, never skipped. Apply the right discount and tax at the right moment. Move each subscription through a strict lifecycle. Keep finance honest in real time. Brightloop does all of it on a real relational database.

🔁
Recurring billing
One invoice per subscription per period, idempotent by design.
🏷️
Discounts & tax
Applied automatically on the next invoice, stop when they expire.
🔐
Role-based access
Admin, staff and customer each see exactly what they should.
Architecture · 3-tier

Thin routes, pure rules, real SQL.

React SPA
Vite + Tailwind. Every form and chart calls /api with a JWT in the header.
→
Express API
authenticate → requireRole → Zod validate → thin routes → transactional services → pure domain rules.
→
PostgreSQL 16
Parameterised SQL, row locks, and SQL views for dashboard figures.

Business logic lives in src/domain (pure, unit-tested) and src/services (transactions). No static JSON, no BaaS — every value you'll see is read from or written to Postgres.

Validation & role separation

Everyone sees exactly what they should.

AAdmin
  • Catalogue & staff
  • Plans, taxes, discounts
  • Everything staff can do
SStaff
  • Subscriptions & invoices
  • Run billing, payments
  • Admin setup
CCustomer
  • Own subscriptions only
  • Own invoices only
  • Any staff route → 403

A weak password is refused with a field-level error from both client and server. Sign in as the customer and the admin screens simply aren't there — enforced by requireRole, re-checked on every request.
